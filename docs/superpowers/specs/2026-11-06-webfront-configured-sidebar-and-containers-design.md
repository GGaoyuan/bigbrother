# Webfront 配置驱动侧栏与内容容器

## 意图

让侧栏文案和导航从应用启动时加载的全局配置读取，并将侧栏动作与右侧内容容器解耦。后续增加工作区、数据分类或页面时，主要通过扩展配置完成；运行逻辑依赖稳定的 ID 和类型，不依赖中文显示文案。

## 用户目标

- 启动时读取项目配置，并保存在全局状态中，供侧栏及容器使用。
- 数据、AI、页面三个侧栏 Tab 的 ID、类型和显示文案来自配置。
- 点击数据 Tab 时，右侧容器显示数据工作台页面。
- 点击页面导航项时，右侧容器显示对应路由页面。
- 内容容器维护一个配置队列；重复打开相同 ID 时复用已有配置，并通过 KeepAlive 缓存已访问组件。

## 约束与范围

- 使用现有 Vue 3、Vue Router、Pinia，不增加依赖。
- 显示文案与行为标识分开；分支和校验基于 ID / type 常量或联合类型。
- 现有侧栏数据分类和页面导航保留；“数据工作台”状态栏继续独立固定在侧栏底部。
- AI 主内容仅提供空白占位页面。
- 容器队列为应用运行时状态，不要求持久化到磁盘或服务端。

## 设计

1. `src/common/appConfig.ts` 定义类型化配置：工作区 Tab、数据分类及模拟数据、指标、页面导航和侧栏静态文案。配置项使用稳定 ID 与 type，并保留独立 label。
2. `src/common/appConfigStore.ts` 通过 Pinia 在启动时载入配置并全局暴露。`main.ts` 等待配置初始化后挂载应用。
3. `src/common/containerQueue.ts` 保存内容容器配置队列与当前容器 ID。数据页、AI 页和路由页面采用不同的联合类型；用稳定 ID 去重和激活。
4. Sidebar shell 与顶部切换区放在 `src/views/sidebar/`；数据侧栏内容放在 `src/views/data/`，页面导航内容放在 `src/views/pages/`，AI 内容放在 `src/views/ai/`。
5. `App.vue` 管理主框架，Sidebar 发出工作区或页面选择；各侧栏内容组件从全局配置取文案和菜单数据。
6. `src/views/workspace/WorkspaceContainer.vue` 根据活动容器类型显示数据页、AI 占位或 Vue Router 当前路由组件，并用 KeepAlive 保留访问过的路由组件状态。
7. 默认进入数据工作区并打开数据主页；点击页面导航时将对应页面容器加入队列并路由到目标页面。返回已打开的容器时复用同一队列项。

## 验收条件

- 初始挂载前已完成全局配置加载；三个 Tab 的行为判断使用 ID/type，不比较显示文案。
- 修改 Tab、页面或分类文案不需要改动判断逻辑。
- 点击数据 Tab 会在主区域显示数据页面。
- 点击任意页面导航项会显示对应路由页面，容器配置队列去重且保留已访问页面组件状态。
- AI Tab 显示 AI 主内容占位，底部“数据工作台”文案始终固定在侧栏外层。
